# P2 答辩设计（未编码）

以下方案用于口述扩展，不属于当前已实现功能。

## 多节点集群模拟

保留一个Ray Head，在同机容器或多台机器启动Worker节点，每个节点声明CPU配额和自定义标签。平台资源接口返回每节点的总量、预留、可用和实际利用率；提交任务由Ray选择满足资源的节点。

当前单机本地文件路径、psutil进程清理不能直接用于跨节点。扩展时将进程管理留在各节点worker，使用控制消息取消；日志、指标、产物写共享对象存储。任务记录保存节点ID和执行ID，节点失联时先标记可疑、保留预留并核对执行结果，避免错误重跑。

若API扩为多个副本，需要单独调度服务或带fencing token的租约选主，并将SQLite迁移为支持多实例事务的数据库。Redis锁不能单独替代防止过期持有者继续写入的保护。

## 训练流水线：预处理 → 训练 → 评估

增加 pipeline、step、attempt 三层记录。step保存依赖、输入产物和资源请求；只有前置步骤成功后才进入现有任务队列。各步骤独立申请和释放CPU，避免整个流水线持续占用资源。

失败重试针对具体attempt执行，区分可重试的临时错误与参数错误；用户取消不自动重试。成功步骤不重复执行，整个流水线取消时停止运行步骤、取消未启动步骤。各步骤通过产物ID衔接，不依赖节点私有路径。

## 数据集与模型产物

数据集记录ID、版本、校验和、格式、训练/验证划分和对象存储地址；训练提交绑定不可变版本。上传后检查路径穿越、格式和大小，避免不同任务修改同一份数据。

模型产物包含任务ID、attempt、模型格式、大小、校验和和指标摘要。worker上传产物成功后再写入完成记录，API生成有时效的下载链接。对象存储做内容保存，数据库只保存元数据；配额与保留策略用于防止磁盘无限增长。

## 状态变更 Webhook

在更新任务状态的同一个数据库事务中追加outbox事件，由独立发送器投递。事件包含event_id、任务ID、attempt、前后状态、发生时间和序号。

投递采用至少一次语义、指数退避重试和死信列表，接收端按event_id幂等。使用签名、时间戳和重放窗口验证来源。对目标地址做SSRF防护和超时限制，禁止访问本机/内网元数据端点；失败投递不能阻塞任务状态落库或资源回收。
